# 專案規劃

將 Brainstorming 與 Planning with Files 合併為一條受控流程。只為確實需要跨階段保存決策的大型工作建立規劃檔案。

## 判斷是否啟用

符合任一條件時啟用：

- 建立新專案或大型新功能。
- 工作橫跨多個模組、資料格式或部署階段。
- 涉及重要架構取捨、資料遷移或相容性風險。
- 預期需要多次工作階段，必須保存進度。
- 使用者明確要求實作計畫或工作拆解。

以下情況不建立規劃檔案：

- **純產品方向探索與動態問卷訪談**：當使用者要求「幫我規劃產品」、「透過問卷引導我」、「幫我重新評估這個專案」且尚未要求建立實作檔案或修改 Repository 時，優先依 `lianghao-development` 之 `references/project-product-assessment.md` 第 5 節進入預設唯讀之引導式需求探索模式（動態問卷 ➜ 主動分析比較 ➜ 產出 11 項產品方向決策摘要），未經明確要求不寫入 Repository。
- 明確且局部的 Bug。
- 單一欄位、按鈕、文字或 CSS 調整。
- 已提供完整替換規格，且不涉及架構選擇。
- 唯讀說明、摘要或狀態查詢。

## 執行流程

1. 先讀取適用的 `AGENTS.md`、既有架構、相關程式碼及現有規劃文件。
2. 若使用者要求透過問卷探索產品方向或需求尚未收斂，先依 `lianghao-development` 之 `references/project-product-assessment.md` 第 5 節完成動態訪談與決策摘要；若需求已確定並要求開始實作，直接進入拆解與執行，不重新啟動問卷。
3. 優先更新既有的 `IMPLEMENTATION_PLAN.md`、`plan.md` 或 `tasks.md`，不得為同一任務建立重複文件。
4. 專案尚無規劃文件且工作確實跨階段時，只建立一份 `IMPLEMENTATION_PLAN.md`。
5. 依最小可驗證單位拆解工作，記錄相依關係、風險與驗證方式。
6. 實作期間持續更新狀態；只有完成真實驗證後才能標記完成。
7. 結束時記錄實際結果、剩餘問題與下一個可執行步驟。

## 規劃文件格式

```markdown
# 實作計畫

## 目標與驗收條件

## 不做範圍

## 現況與限制

## 已確認決策

## 工作清單
- [ ] 工作項目｜驗證方式

## 風險與因應

## 驗證紀錄

## 剩餘問題
```

## 維護規則

- 只記錄目前任務需要的資訊，避免複製整份 `AGENTS.md`。
- 保留已確認的歷史決策；變更決策時補記原因，不直接抹除。
- 不以規劃取代實作，不為小任務增加儀式性文件。
- 不虛構測試、完成狀態、時間估算或外部依賴狀態。
- 發現使用者既有修改時保留並註記，不自行覆蓋。
