# Python 環境修復

適用於環境盤點、入口版本混用、相依隔離與 Portable runtime 修復。

- 先記錄 Git 狀態、直譯器完整路徑、版本、pyvenv.cfg、套件 metadata 與實際入口；保護既有未提交修改。
- 所有套件操作使用已確認直譯器的 `-m pip`；不得裸跑 `pip`，也不得假設 `python`、`py`、`py -3` 指向同一版本。
- 版本依專案宣告及目前可運作的環境選擇。先隔離、驗證，再評估升級；不為統一版本變更 PATH 或全域套件。
- 虛擬環境直接建立於最終路徑，不搬移既有 .venv。既有損壞環境保留，不由啟動器自動刪除。
- 開發 .venv 與 embedded 發布 runtime 分別驗證。缺少 Tcl/Tk 時不可只複製其他版本 DLL；免安裝能力須以乾淨環境實測證明。
- embedded 啟動、測試、子程序及更新後重啟均明確使用 `-s`；以 `site.ENABLE_USER_SITE`、`sys.path`、套件來源及 `pip check` 驗證。不為隔離逕改 `._pth`。
- 啟動器優先使用專案環境；版本不符或環境缺失提供指引，不靜默改用全域 Python。檢查模式須唯讀；正常啟動不反覆安裝已就緒的依賴。
- 鎖定清單來自已驗證的專案環境，不能直接把整份全域 freeze 當作專案需求。OpenCV 多種 distribution 共用 cv2，不能直接解除安裝其中之一而假設其他仍完整。
- Git 解除 runtime 追蹤前，先預覽檔案，確認重建方式及本機檔案保留；不重寫 Git 歷史或刪除既有發布包。
- 驗證涵蓋套件完整性、核心回歸、實際桌面入口及含中文／空白的替代路徑。使用合成資料或複本；不以原始相片、案件資料或影音作修復測試。
- 完成後記錄通過證據、尚未驗證的跨機／跨版本邊界與回復方式，更新單一 HANDOFF。達成目標後停止擴大修改。
