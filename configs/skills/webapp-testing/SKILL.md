# 網頁應用程式測試

## 執行順序

1. 先讀取專案的測試與啟動設定；沿用既有 `package.json`、Playwright 設定、測試指令或本機伺服器。
2. 依環境工具優先序驗證 `http://localhost` 或安全的 `file://` 靜態頁面，等待可驗證的 DOM 狀態而非僅靠固定等待時間：
   - **Antigravity**：互動式頁面操作、視覺檢查與截圖優先委派給內建 `browser` subagent；如需腳本化 DOM/網路檢測再使用環境已掛載的 `playwright` MCP 或 `chrome-devtools` MCP。
   - **Codex / Claude Code**：優先使用各自內建瀏覽器或已配置的 MCP 工具。
3. 專案已具備 Node.js Playwright 時，才執行它既有的測試指令。不得為單次驗證執行 `pip install playwright`、下載瀏覽器或新增測試框架。
4. 優先使用 `data-testid`、accessible role、label 選擇器；驗證主要流程、網址狀態、關鍵文字與錯誤訊息。
5. 記錄必要的截圖、console error、未捕捉例外與實際操作結果；測試資料不得影響正式資料。

## UI 修改前後與響應式驗收

- 實測前記錄版本、路由、測試資料／狀態、瀏覽器版本、viewport（CSS px）、device scale factor、頁面縮放與主題；修改後使用相同條件擷取證據。等待必要 DOM、字型與目標區域圖片就緒；長頁按需捲動觸發 lazy 圖片，不無限等待尚未進入畫面的資源，等待須有逾時與失敗紀錄；可固定動態資料以便比較，但不得隱藏待測內容或藉此掩蓋缺陷。
- 依變更挑選受影響的尺寸與狀態。單一元件的局部修正先測問題出現的尺寸與狀態，涉及斷點時加測兩側。跨頁或共用版面變更沿用專案支援尺寸，未定義時可取窄（390×844）、中（768×1024）、寬（1440×900）作代表。
- 僅在變更涉及長文字、空／錯誤狀態、導覽或彈窗時加測對應情境。檢查受影響畫面是否溢出、重疊、截字或無法操作。桌面網頁涉及文字、版面重排、操作可達性或有明確驗收要求時，以 200% 頁面縮放複驗；工具無法調整真實頁面縮放時列略過，單獨記錄窄 viewport 結果。
- 重走受影響操作。互動或資料流程有變更時，加測對應的鍵盤操作、錯誤復原和資料保存，並檢查 console error。觸控相關變更需實際合成手勢或裝置測試；窄 viewport 截圖不等於觸控通過。離線產品以已知本機資源及測試資料檢查斷網行為，不載入外部掃描服務。
- 遇到重複送出、延遲回應或操作中斷相關變更，額外測試重複點擊、請求失敗與復原後再操作，確認不重複寫入、不遺失輸入；不將所有無關狀態擴為每次必測。
- 視覺差異測試僅使用既有專案設定，不因差異失敗直接更新 golden；先判斷是否為預期變更，保留基線與理由。設計缺陷分類與報告欄位沿用 [UI 審查流程](../product-design/references/ui-review.md)，無障礙專項依 [accesslint](../accesslint/SKILL.md) 的適用條件執行。

## 回報

- 清楚標示通過、失敗或略過，以及實際測試情境。
- 失敗時提供可重現步驟、預期與實際結果、相關選擇器或畫面證據。
- 沒有可用伺服器、既有測試或 Browser 存取權限時，如實標示限制，不宣稱已完成 UI 驗證。
