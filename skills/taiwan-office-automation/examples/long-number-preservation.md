# 長數字與帳號完整性保護範例 (Examples: Long Number Preservation)

## 1. 錯誤 vs 正確處理對比
| 欄位類型 | 原始真實值 | ❌ 錯誤處理 (自動轉數值) | ✅ 正確處理 (強制純文字) |
| :--- | :--- | :--- | :--- |
| 銀行帳號 | `0040012345678901` | `40012345678901` (前導零丟失) | `'0040012345678901'` |
| 涉案帳號 (長度 16) | `9876543210987654` | `9.87654E+15` (末位精度失真) | `'9876543210987654'` |
| 行動電話 | `0912345678` | `912345678` (首位 0 丟失) | `'0912345678'` |
| 涉案金額 | `1500000` | `'1500000'` (未格式化不易閱讀) | `NT$ 1,500,000` (數值格式化) |

## 2. CSV 生成防禦語法範例（可信內部 Excel 雙擊相容選項）
若輸出明確專供基層行政同仁以 Excel 雙擊檢視，且無外部資料交換與公式注入風險：
```csv
項次,身分證號,銀行代碼,帳號,交易金額
1,"=""A123456789""","=""004""","=""0040012345678901""",150000
```
> ⚠️ **注意**：`="值"` 係將資料轉為試算表公式顯示，僅供可信之 Excel 快速檢視工作流；標準跨系統 CSV 交換應保持原值，並改由匯入端或原生 XLSX 格式明確設定純文字欄位。
